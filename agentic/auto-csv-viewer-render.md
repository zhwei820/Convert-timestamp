# CSV Viewer 渲染纪律（Convert-timestamp 项目专属）

## 何时触发

- 修改 `src/csv-viewer.html` / `src/csv-parser.js` / `src/csv-viewer.js` / `src/csv-drop-preview.js` 中的表格样式或行为
- 需要在"独立预览页"和"拖拽后新窗口预览"两种入口共享同一份改动
- 需要让 CSV 表格出现横向滚动条
- 需要在 `buildViewerHtml()` 生成的 blob-URL 新窗口里加交互（如复制、排序、搜索）
- 讨论"能否使用某剪贴板/存储 API"时

## 核心事实

### 双渲染入口

CSV 表格有两个渲染入口，且都产出**独立的完整 HTML 上下文**：

1. **静态扩展页**：`csv-viewer.html` + `csv-viewer.js`；`chrome-extension://<id>/src/csv-viewer.html`；上下文是 extension origin。
2. **动态 blob 新窗口**：`csv-drop-preview.js` 里通过 `URL.createObjectURL(new Blob([buildViewerHtml(...)]))` + `window.open` 打开；上下文是 **blob origin，属于普通页面**，不是扩展页面。

### CSS 双副本

同一份表格样式在两个地方都有：

- `src/csv-viewer.html` 里 `<style>` 块（静态页专用，含 `.dropzone` / `.hidden` 等页面专属类）
- `src/csv-parser.js` 里 `buildViewerHtml()` 返回字符串中的 `<style>` 块（新窗口专用）

**任何影响表格视觉/交互的 CSS 改动必须两处同步**，否则两个入口体验会漂移。曾多次出现"只改一处，另一入口没变"的问题。

### 行为逻辑用 `.toString()` 共享

避免 JS 双副本的做法：把行为逻辑写成**纯函数**（不捕获闭包，只用参数 + DOM API），
- 静态页：`csv-viewer.js` 直接调 `utils.attachColumnCopy(tableWrap)`
- 新窗口：`buildViewerHtml()` 里用 `${attachColumnCopy.toString()}` 内联到 `<script>` 中，末尾 `attachColumnCopy(document)` 触发

**要点**：
- 函数必须纯——不能引用 `utils`、外部变量。
- 函数体里含反引号 / `${}` 不影响外层 template literal 解析，`.toString()` 返回的是字符串值。
- 函数体里不能有字符串字面量 `</script>`，否则会提前关闭 script 标签（本项目未触及）。

## 关键陷阱

### 陷阱 1：CSS `max-width` 单独用不会让多列 table 出现横向滚动

`<table>` 默认 `table-layout:auto`——浏览器为了塞下所有列会把每列压缩到远小于 `max-width`，只要总宽 ≤ 视口就不溢出，`overflow-x:auto` 也不会触发。

**修复姿势**：给 `th`/`td` 加 `min-width`（本项目定为 120px）；或改 `table-layout:fixed` + 显式列宽。仅靠 `max-width` 是"上限"而非"下限"，无法逼出横滚。

**教训**：CSS 布局承诺（"会/不会溢出"、"会/不会滚动"）不能凭 `overflow-x:auto` 或 `max-width` 单个属性推断，必须考虑 `min-width` / `table-layout` / `word-break` 的交互，或本地实测。

### 陷阱 2：`clipboardWrite` 权限对 blob-URL 页面无效

- Chrome 扩展 `manifest.json` 的 `clipboardWrite` **只对 extension origin 和 content script 生效**。
- `buildViewerHtml()` 生成的 blob 新窗口是**普通页面上下文**——走浏览器标准 Clipboard API + 用户手势规则，不受扩展权限约束。
- 因此在描述"复制功能是否需要额外权限"时，不要笼统说"`clipboardWrite` 已在 manifest 里"——那对 blob 页面不适用。
- 兜底：`navigator.clipboard.writeText` 失败时用 `document.execCommand("copy")`（本项目已如此）。

### 陷阱 3：渲染后忘记挂行为

`renderTableHtml()` 只产生 HTML 字符串，**不带任何 event listener**。渲染完必须显式调 `utils.attachColumnCopy(root)`（静态页）或依赖 `buildViewerHtml()` 里的 IIFE 自动调用（新窗口）。新增功能（如列排序、单元格搜索）时须同样处理，否则新窗口能用而静态页失效（或反之）。

### 陷阱 4：`th` 里有 `.idx` 序号前缀，`textContent` 会带上序号

表头结构：`<th data-col="..." data-value="..."><span class="idx">1</span> headerName</th>`

- 想要**纯表头文本**：读 `th.getAttribute("data-value")`
- 直接用 `th.textContent` 会得到 `"1 headerName"`

复制列、列名匹配、导出等场景务必用 `data-value`。

## 修改 checklist

改任何表格样式/结构时：

- [ ] `csv-parser.js` 里 `buildViewerHtml()` 的 inline `<style>` 是否需要同步？
- [ ] `csv-viewer.html` 的 `<style>` 是否需要同步？
- [ ] `renderTableHtml()` 的 DOM 结构变了 → 两处的 CSS 选择器都要跟着变
- [ ] 新增了行为 → `attachColumnCopy` 类的纯函数写法 + 两处入口都要挂
- [ ] 涉及"多列是否横滚" → 用 `min-width` 而非 `max-width`
- [ ] 涉及剪贴板/存储 → 区分 extension origin vs blob origin，走的 API 权限模型不同
